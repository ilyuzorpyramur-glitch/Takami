Репозиторий: `ilyuzorpyramur-glitch/Takami` (форк, Apache-2.0). Правки → коммит → push.
Сборка и тесты — только в GitHub Actions.

Работай **в отдельной ветке** `takami/etap10-heal`. В `main` не мержить: параллельно идёт

## Твои границы

Ты работаешь **только с кодом**: реализация, гейт, тесты, протокол, инструмент отчёта.
Живой прогон по сайтам делает оператор на своём устройстве и присылает файл.

Поэтому:

- не запускай `./gradlew` локально, не устанавливай APK, не «проверяй на эмуляторе»;
- не пиши в отчёт и в чат числа, которых у тебя нет: если прогона не было, чисел нет;
- не подгоняй правила лечения под предполагаемый результат конкретного сайта — только под
  то, что код может доказать сам;
- если для проверки не хватает данных — так и скажи, вместо того чтобы выдумать.

## Где ты находишься

Этапы 1–8 приняты в `main`. Код генератора: `app/src/main/java/eu/kanade/tachiyomi/takami/`.
Гейты: `.github/scripts/`, протоколы: `.github/`, отчёты: `reports/`.
`SPEC_VERSION` сейчас `3` (`takami/spec/SpecVersion.kt`) — **не поднимать**.
Версия приложения считается из `getCommitCount`, отдельного `extVersionCode` в Takami нет.

Что уже есть и работает — на этом и строй:

- `Forge.build(url)` — собирает спеку с живой страницы: движок, селекторы карточек, пагинация.
- `SelfCheck.report(spec)` — прогон по шагам (`catalog`, `pagination`, `details`, `episodes`,
  `video`) и вердикт по каждому. **Не править**, использовать как есть.
- `TakamiForge.save(spec, failedChecks)` — уже делает главное: штампует версию, пишет её в
  историю, сравнивает число пройденных проверок и откатывается, если стало хуже
  (`SpecRollback.apply`), а причину кладёт в `SpecJournal`.
- `SpecHistory` — три последние рабочие версии на источник, откат возвращает спеку целиком.
- `SpecJournal` (`spec/SpecRollback.kt`) — журнал откатов, JSONL, битые строки пропускает.
- `Fetcher` — очередь, 1 запрос на домен, пауза 1 500 мс, бюджет 300/сутки, брейкер.
- `ParseFailures.noteFailure(host, step, тип, версия)` — провалы без текста страниц.
- `Sweep` — прогон списка сайтов, умеет продолжаться после обрыва.

То есть **решение «принять или откатить» уже написано**. Твоя работа — не переписать его, а
сделать шаг до него: понять, что именно сломалось, и предложить правку **только этой части**.

## Что должно получиться

Источник, который перестал открываться, чинится сам: приложение замечает, что сломался
конкретный шаг, заново смотрит живую страницу, меняет **только сломанную часть** спеки,
проверяет и оставляет правку лишь если стало строго лучше, а остальное не испортилось.
Не получилось — возвращается прошлая версия, источник продолжает работать как работал, а в
журнале остаётся строка «домен, шаг, попытка, чем кончилось».

Чего быть не может: фонового лечения без ведома пользователя, бесконечных попыток, тихой
подмены спеки «похожей», лечения сайта, который никогда не работал, и лечения видео —
видео целиком принадлежит этапу 9.

## Жёсткие правила

1. Сборка только в CI: `./gradlew :app:assembleDebug -Ptakami.abi=x86_64`. Один APK, x86_64.
2. **`SPEC_VERSION` остаётся `3`**, поля спеки не добавляются вовсе: лечение работает на тех
   полях, что уже есть. `SpecVersion.kt`, `SpecMigration.kt` не трогать.
3. `kodikdreamcast` (dreamerscast.com) — только чтение: не лечить, не править спеку, не
   трогать `applicationId`, подпись, языковой фильтр. Пропуск оформляется кодом и тестом, а не
   комментарием.
4. Никаких ключей, токенов, cookies в коде, логах, спеках, коммитах, отчётах. Токена Kodik
   не должно быть нигде; в названиях источников слова «Kodik» быть не может.
5. Вся сеть — через `Fetcher`. `OkHttpClient` наружу не выставлять, `Jsoup.connect` не
   вызывать. Один сайт за раз, 403/капча — стоп по домену на сутки, капчу не обходим.
6. Лечение **никогда не запускается само**: ни в `TakamiForge.init`, ни в `Application`, ни по

7. В тестах и гейте **сети нет вообще**: ни `Jsoup.connect`, ни `OkHttpClient`, ни живых

8. Ktlint: `indent_size = 4`, `max_line_length = 120`. Комментарии по-русски, без `TODO`.
   Тексты интерфейса — русские, без англицизмов.
9. Отчёт, журнал и телеметрия без приватного: только домен, шаг, короткий тип, числа. Ни

## Шаг 1. Что сломалось

`heal/HealPlanner.kt` — чистая функция, без сети:

```kotlin
/** Часть спеки, которую чиним. */
enum class SpecPart { CATALOG, CARD, EPISODES, PAGINATION, NONE }

object HealPlanner {
    /** По провалившимся шагам решает, какую часть спеки чинить. */
    fun plan(failed: List<String>): SpecPart
}
```

Правила:

- `catalog` и `pagination` провалились вместе → `CATALOG` (сначала карточки, потом страницы);
- только `pagination` → `PAGINATION`;
- `details` (карточка тайтла) → `CARD`;
- `episodes` → `EPISODES`;
- `video` → `NONE`: ось видео на этом этапе не лечится, в журнал идёт `skipped/video_owned`;
- пусто → `NONE`.

Ключи шагов — ровно те, что уже отдаёт `SelfCheck`: `catalog`, `pagination`, `details`,
`episodes`, `video`. Свой словарь шагов не заводить.

Порядок старшинства при нескольких провалах: `CATALOG`, `CARD`, `EPISODES`, `PAGINATION`.
Одна попытка лечит **одну** часть.

## Шаг 2. Можно ли лечить

`heal/HealPolicy.kt` — чистая функция от состояния, времени и журнала:

```kotlin
data class HealState(
    val attemptsToday: Int = 0,
    val lastAttemptAt: Long = 0L,
    val lastFailedAt: Long = 0L,
    val failedInRow: Int = 0,
)

sealed interface HealAllow {
    data object Yes : HealAllow
    data class No(val reason: String, val retryAfterMs: Long = 0L) : HealAllow
}

object HealPolicy {
    fun allow(host: String, part: SpecPart, state: HealState, journal: List<SpecJournalEntry>, now: Long): HealAllow
}
```

Запреты (каждый — отдельная причина, тестом):

| причина | когда |
|---|---|
| `read_only` | домен `dreamerscast.com` или хост `kodikdreamcast` |
| `video_owned` | `part == NONE` из-за видео |
| `never_worked` | в истории нет ни одной версии и `checksPassed == 0` |
| `attempts_today` | `attemptsToday >= 2` |
| `cooldown` | после провала прошло меньше 6 часов |
| `cool_down_hard` | два провала подряд: ждать 24 часа |
| `no_breakage` | в журнале нет провала этого шага |

Константы — именованные, в одном месте: 2 попытки в сутки, 6 и 24 часа.

## Шаг 3. Правка одной части

`heal/HealMerge.kt` — чистая функция:

```kotlin
object HealMerge {
    /** Старая спека + свежая сборка → спека с заменённой одной частью. */
    fun merge(current: SiteSpec, fresh: SiteSpec, part: SpecPart): SiteSpec
}
```

- заменяется только секция выбранной части (`catalog`, `details`, `episodes`, пагинация);
- **никогда** не меняются `name`, `lang`, `sourceId`, `baseUrl`, `iconUrl`, `iconPath`,
  `filters`, `video`, `dubbings`, `search`, `version`, `checksPassed`, `updatedAt`;
- если во `fresh` нужной секции нет (пустые селекторы) — возвращается `current` без изменений,
  а `Healer` считает попытку провальной с типом `no_alternative`;
- функция идемпотентна: `merge(merge(a, b, p), b, p) == merge(a, b, p)`.

## Шаг 4. Вердикт

`heal/HealVerdict.kt` — чистая функция, строже, чем общий счёт проверок:

```kotlin
object HealVerdict {
    /** Можно ли оставить правку: сломанный шаг починился, остальные не хуже. */
    fun accept(before: List<CheckResult>, after: List<CheckResult>, part: SpecPart): Boolean
}
```

- правка принимается, только если шаг, который лечили, стал `ok`;
- и **ни один** другой шаг не перестал быть `ok`;
- равенство общего счёта при всё ещё сломанном шаге — отказ (это и есть дыра в счёте);
- пустой `after` — отказ.

`Healer` при отказе **не вызывает** `TakamiForge.save` с новой спекой: он берёт прошлую версию
из `SpecHistory` и оставляет её текущей, а в журнал пишет `rejected` с причиной. `save` со
своим откатом остаётся последней страховкой, а не единственной.

## Шаг 5. Оркестрация

`heal/Healer.kt`:

```kotlin
class Healer(private val forge: Forge = Forge(), private val selfCheck: SelfCheck = SelfCheck()) {
    suspend fun heal(spec: SiteSpec, trigger: String): HealResult
}
```

Порядок: `HealPolicy.allow` → `SelfCheck.report(current)` (что именно провалилось сейчас) →
`HealPlanner.plan` → `Forge.build(baseUrl)` → `HealMerge.merge` → `SelfCheck.report(merged)` →
`HealVerdict.accept` → `TakamiForge.save` или возврат прошлой версии → `HealLog`.

- `trigger` — `"user"` или `"sweep"`; других значений нет;
- сетевые потолки — те же, что у `Fetcher`: лечение не повышает бюджет и не обходит брейкер;
- 403/капча на сборке — `blocked`, попытка не засчитывается как «плохая спека», но домен
  остывает сутки;
- исключение внутри лечения не выходит наружу: `runCatching`, результат `failed`, спека не
  меняется.

`HealResult`: `healed` (да/нет), `part`, `reason` (короткий код), `before/after` по шагам.

## Шаг 6. Журнал

`heal/HealLog.kt` — JSONL в `filesDir/takami/heal.jsonl`, одна строка на попытку:

```
{"host":"…","part":"CARD","attempt":1,"decision":"accepted","reason":"","before":"catalog+;details-;episodes-","after":"catalog+;details+;episodes-","trigger":"user","at":0}
```

- только домен, часть, номер попытки, решение, код причины, плюс-минус по шагам и время;
- ни адресов с путями, ни названий, ни текста страниц, ни cookies;
- битые строки пропускаются, журнал не мешает работе;
- файл ограничен: не больше 500 строк, старые обрезаются (иначе он растёт вечно);
- `HealLog.state(host, now)` отдаёт `HealState` для `HealPolicy` — второй копии счёта нет.

`SpecJournalEntry` дополняется тремя полями с дефолтами (`part`, `attempt`, `decision`), чтобы
история откатов и история лечения читались одним журналом. Старые строки читаются как раньше.
