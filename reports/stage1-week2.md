## Что сделано

Пакет `app/src/main/java/eu/kanade/tachiyomi/takami/fetch/`:

| Файл | Что внутри |
|---|---|
| `CacheEntry.kt` | Метаданные записи: адрес, referer, ETag, Last-Modified, время получения, срок жизни с разбросом, отпечаток начала страницы, полный размер, кодировка, имя файла тела, время последнего обращения. |
| `HttpCache.kt` | Дисковый кэш в `cacheDir/takami-http`: тело каждой страницы отдельным файлом, индекс одним JSON. Запись атомарная (временный файл + переименование). Вытеснение по числу записей и по объёму — первыми уходят самые давно использованные. Битый индекс читается как пустой, отсутствующее тело считается промахом. |
| `Conditional.kt` | Заголовки `If-None-Match` и `If-Modified-Since`, разбор ответа 304, отпечаток первых 4 КБ и сверка полного размера. |

`Fetcher.page()` теперь идёт по цепочке: память → диск → сеть. Результат кладётся
в оба уровня. Если сайт недоступен, отдаётся последняя сохранённая страница.

### Почему referer входит в ключ

Часть сайтов отдаёт по referer разную разметку: страница серии, открытая из
каталога и из карточки тайтла, может отличаться блоками и порядком элементов.
Склейка таких ответов в одну запись иногда показывала бы разметку чужого
перехода, поэтому ключ — адрес плюс referer. Плата: две записи на один адрес при
разных переходах, объём ограничен потолком и вытеснением.

### TTL и разброс

Срок жизни — сутки плюс-минус два часа. Смещение считается детерминированно от
имени источника, поэтому один сайт всегда получает один и тот же срок, а разные
устройства расходятся между собой и не обновляются синхронно. Срок хранится в
самой записи: после перезапуска он не пересчитывается.

## Приёмка

| Требование протокола | Где проверяется |
|---|---|
| Хранение в `cacheDir` | `HttpCache(Context)` строит папку от `context.cacheDir` |
| Потолок 32 МБ, вытеснение LRU | `HttpCacheTest.старые записи вытесняются при превышении потолка` — потолок 2 КБ, шесть записей, самая старая исчезает |
| TTL 24 часа ±2 часа | `HttpCacheTest.ttl сутки и разброс в пределах двух часов`, плюс проверка, что разные источники получают разный срок |
| Атомарная запись | `HttpCache.writeAtomically`: временный файл и переименование |
| Свежая запись без сети | `HttpCacheTest.повторный вход в тот же адрес не идёт в сеть` — `requestCount == 1` |
| 304 → сохранённое тело | `HttpCacheTest.304 отдаёт сохранённое тело без разбора` — второй ответ 304, тело прежнее, `requestCount == 2` |
| Без ETag — сверка отпечатка | `HttpCacheTest.изменённая страница заменяет запись` и `правка в хвосте страницы тоже замечается` |
| Кэш не ходит в сеть сам | в `HttpCache` нет ни клиента, ни вызовов сети |
| Битый файл не роняет | `HttpCacheTest.битый индекс читается как пустой`, `битое тело считается промахом` |
| Офлайн показывает последнее | `HttpCacheTest.без сети отдаётся последняя сохранённая страница` |
| Регрессия этапа 1 | R1 зелёный: все 41 гейт этапа 1 проходят |
