# Этап 1, неделя 1 — каркас сети

Дата: 2 ноября 2026. Ветка: `stage1/week1-network`.

## Что сделано

Новый пакет `app/src/main/java/eu/kanade/tachiyomi/takami/fetch/`:

| Файл | Что внутри |
|---|---|
| `Fetcher.kt` | Единая точка HTTP: `get`, `head`, `post`, `probe`. Внутри — `OkHttpClient` с пулом соединений, gzip, HTTP/2, cookie-jar в памяти, таймауты 20/20 с. Наружу клиент не отдаётся: конструктор `internal`, готовый экземпляр — только через `Fetcher.get()`. |
| `HostGuard.kt` | Лимиты домена: 2 общих слота на приложение, по одному запросу на домен, минимальный интервал 1500 мс, средний темп 0.2 rps со всплеском 2, пауза после 429 на срок из `Retry-After`. Часы подменяются — тесты не ждут реальное время. |
| `RequestBudget.kt` | Дневной счётчик запросов на домен: JSON-файл `filesDir/takami/network-budget.json`, запись атомарная (временный файл + переименование). Ключ содержит дату, поэтому сброс в полночь получается сам; при смене дня карта доменов начинается с нуля, старые записи не копятся. Битый файл читается как пустой счётчик. |
| `FetchLimits.kt` | Все лимиты из задания одной таблицей констант: менять только по согласованию. |
| `HttpErrors.kt` | `FetchError` и наследники: `HttpStatusError` (с `retryAfterMs`), `DailyLimitReached`, `NetworkError`, `InvalidUrlError`. Тексты — русские, без query string в адресах. |

Изменения вне пакета:

- `SpecEngine.kt` — все вызовы переведены на `Fetcher`; сигнатуры `fetch(url, referer)` и `probe(url, referer)` сохранены. Свой `OkHttpClient`, `defaultClient` и `USER_AGENT` из движка удалены.
- `TakamiForge.kt` — `Fetcher.init(context)` вызывается из `TakamiForge.init(context)`, то есть до первого запроса к сайту.
- Заголовки задаются в одном месте: Chrome 124 Android (`Mozilla/5.0 (Linux; Android 13; Pixel 7) … Chrome/124.0.0.0 Mobile Safari/537.36`), `Accept-Language: ru,en;q=0.9`, браузерный `Accept`, `Referer` — если передан.
- `ensureActive()` вызывается дважды: до постановки в очередь и после ожидания лимитов, перед самим запросом. Уход с экрана отменяет и ожидание, и запрос.

## Приёмка недели 1

| Требование | Где проверяется |
|---|---|
| Два запроса к одному домену идут с интервалом не меньше 1500 мс | `HostGuardTest.два запроса к одному домену идут с интервалом не меньше 1500 мс` — реальные часы, время прихода запросов пишет диспетчер MockWebServer |
| 301-й запрос за сутки возвращает `DailyLimitReached` и не идёт в сеть | `RequestBudgetTest.301-й запрос за сутки не идёт в сеть` — 300 запросов проходят, 301-й падает, `server.requestCount == 300` |
| Ответ 429 выставляет `Retry-After`, следующий запрос ждёт | `RetryAfterTest.ответ 429 задаёт Retry-After, следующий запрос ждёт` — виртуальные часы, второй запрос уходит не раньше чем через 3 с; отдельный тест на 429 без заголовка |
| В проекте нет `OkHttpClient` вне пакета `fetch` | `OkHttpScopeTest` — обходит `takami/**` и падает, если `OkHttpClient` встретился вне `fetch/` |

Дополнительно: `RequestBudgetTest` проверяет, что счётчик ведётся по домену, а не по адресу страницы, и что сброс возвращает лимит.

## Сборка

- `.github/workflows/takami-debug.yml`: сначала `:app:testDebugUnitTest --tests "eu.kanade.tachiyomi.takami.fetch.*"`, затем `:app:assembleDebug -Ptakami.abi=x86_64`, затем проверка «в `app/build/outputs/apk/debug` ровно один APK» — шаг падает, если файлов не один. Только после неё артефакт.
- `app/build.gradle.kts`: `-Ptakami.abi` — необязательный параметр. С ним `splits.abi.isEnable = false` и `ndk.abiFilters = [<abi>]`, то есть один APK без ABI-суффикса. Без него splits работают как раньше (все ABI + универсальный APK), релизные сборки не затронуты.
- Новых зависимостей нет: `androidx.datastore` в проект не добавлялся.

## Чего в этой неделе нет

Кэша, условных запросов, повторов, предохранителя, экрана «Диагностика» и версий спеки — по плану это недели 2–4. `HttpCache`, `Retry`, `CircuitBreaker` не заводились даже заглушками, чтобы не пришлось переделывать API.

## Решения по замечаниям ревью

1. **Зависимость `androidx.datastore` убрана.** Счётчик живёт в JSON-файле в `filesDir` с атомарной записью. Общее хранилище предпочтений не взял: счётчики по доменам (до нескольких сотен ключей в сутки) попали бы в общий `getAll()` и в резервные копии пользовательских настроек. Файл изолирован, легко чистится сбросом и проверяется юнит-тестами без Android.
2. **Флаг ABI работает так, как требовалось:** `-Ptakami.abi=x86_64` → `splits.abi.isEnable = false` + `ndk.abiFilters = ["x86_64"]`; без флага — прежние splits с четырьмя ABI и универсальным APK. Плюс шаг CI, который проверяет, что APK ровно один.
3. **`max_line_length = 120`** — как в `.editorconfig`; `.editorconfig` не менялся.
4. **Патч приложен текстом** в ответе: пуша из песочницы нет, доступа к GitHub у сессии нет.

## Открытые вопросы

1. **Проверка «нет OkHttpClient вне fetch»** ограничена пакетом `takami`: в остальном приложении (загрузчик обложек, обновление библиотеки) свои клиенты, и трогать их в этапе 1 нельзя.
2. **Сборка и тесты локально не запускались** — по правилу «сборка только в GitHub Actions». Первый прогон CI и есть проверка компиляции.
