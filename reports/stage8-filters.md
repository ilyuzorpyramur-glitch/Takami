# Этап 8 — фильтры источника из спеки

## Что добавлено

- **Модель:** `takami/FilterSpec.kt` (`FilterSpec`, `FilterOption`); в `SiteSpec`
  одно новое поле `filters: List<FilterSpec> = emptyList()`. Полей в `SiteSpec` стало 19.
- **Состояние и адрес** (`takami/filters/`): `FilterState` — выбор, чужие ключи
  и значения отбрасываются; `FilterUrl.apply` — query (параметры через `&`),
  path (подстановка по `valueTemplate`), sort (один параметр), text (как есть,
  пустое не добавляется); пустое состояние адрес не меняет; `default` из спеки
  работает по нетронутым ключам; `FilterStore` — `filesDir/filters.json` по хосту,
  битый файл даёт пустое состояние; `FilterList` — спека ↔ `AnimeFilterList`.
- **Источник:** `getFilterList()` строит список из активной спеки; `getSearchAnime`
  собирает адрес через `FilterUrl.apply` и передаёт его в `SpecEngine`
  (`fetch` + `parseCatalogue`); выбор сохраняется после успешного запроса.
  Каталог и лента с пустым выбором идут прежним путём, с выбором — через собранный адрес.
- **Сканер:** `Forge.scanFilters(doc)` — списки, флажки с подписями,
  ссылки-сортировки; мусор («Все», «Сбросить») отсекается; сеть не нужна.
  Вызов — при создании спеки в мастере, найденное попадает в `spec.filters`.
- **Экран:** `ui/takami/FilterScreen.kt` + `FilterScreenModel.kt` — «Фильтры
  источника», элементы сверху вниз, «Применить (N)» и «Сбросить», пустой источник
  честно пишет «У источника нет фильтров». Вход — со списка источников в мастере,
  отдельная навигация, без зависимости от экрана качества/озвучки.

## Типы фильтров

`check` (при `maxSelected = 1` — как radio), `select`, `tri` (исключение —
со знаком минус в адресе), `text`, `sort`.

## Версия спеки

`SPEC_VERSION` не менялся (осталось 2); `SpecVersion` / `SpecMigration` /
`SpecRollback` не тронуты. Спека версии 2 без `filters` читается как раньше.

## Чем доказано

- Гейт: `bash .github/scripts/verify-stage8.sh` — 0 FAIL, внутри регрессия этапа 6.
- Тесты без сети (`app/src/test/.../takami/filters/`): адрес для всех типов,
  пустое состояние, мусор в состоянии, битый файл, сборка списка, сканер на фикстуре.
- CI на ветке `takami/etap8-filters`: `assembleDebug` (x86_64) и юнит-тесты зелёные.

## Что осталось

- Направление сортировки не различается: `sort` — один пункт.
- Исключения в `default` (tri со знаком минус) отдельно не проверяются.
