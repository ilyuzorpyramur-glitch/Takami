# Этап 10 — самолечение спеки

## Что добавлено

- **План** (`heal/HealPlanner.kt`): по провалившимся шагам самопроверки — одна
  часть: каталог, карточка, серии, пагинация. Видео не лечится (ось этапа 9),
  план отдаёт `NONE`.
- **Правила** (`heal/HealPolicy.kt`): только для чтения (`dreamerscast.com`,
  `kodikdreamcast`), видео, источник без истории и проверок, лимит попыток,
  паузы 6/24 часа, требование зафиксированной поломки. Пороги — константы.
- **Правка одной части** (`heal/HealMerge.kt`): заменяется только выбранная
  секция; имя, язык, адрес, иконки, фильтры, видео, озвучки, поиск, версия и
  счёт проверок не меняются; пустая свежая секция — спека без изменений;
  функция идемпотентна.
- **Вердикт** (`heal/HealVerdict.kt`): принять, только если леченый шаг
  починился и никто другой не стал хуже; равенство счёта при сломанном шаге —
  отказ. Правка не сохраняется, прежняя версия остаётся текущей.
- **Оркестрация** (`heal/Healer.kt`): проверка → план → правило → сборка через
  общий `Forge` → слияние → повторная проверка → вердикт → сохранение или
  отказ. Триггеры — `user` и `sweep`. 403/капча дают `blocked`: попытка не
  считается плохой спекой, домен остывает сутки. Исключение не выходит наружу.
- **Журнал** (`heal/HealLog.kt`): `filesDir/takami/heal.jsonl`, строка на
  попытку: домен, часть, попытка, решение, причина, плюс-минус по шагам,
  триггер, время. Не больше 500 строк, битые строки пропускаются,
  `state(host, now)` отдаёт состояние правилу. `SpecJournalEntry` дополнен
  полями `part`, `attempt`, `decision` с дефолтами — старые строки читаются.
- **Экран** (`ui/takami/HealScreen.kt` + `HealScreenModel.kt`): что сломалось,
  «Можно починить» / «Починка недоступна» / «Подождите N ч» из правила, кнопка
  «Починить», «Проверяю страницу» в работе, итог, строки журнала. Вход —
  пункт «Починить источник» в меню расширений. Выдуманных чисел нет.
- **Прогон** (`takami/Sweep.kt`): отметка `healed` и `healReason` в итоге —
  сломанный сохранённый источник лечится в прогоне по общим правилам. В меню
  возвращён пункт «Прогон сайтов», потерявшийся при слиянии.
- **Точки входа**: `TakamiForge.heal(host, trigger)` — явный вызов, из `init`
  лечение не стартует; событие лечения идёт через существующий приёмник
  провалов с шагом `heal`; у `ForgeResult.Failure` есть пометка `blocked`.

## Почему видео исключено

Видео целиком принадлежит этапу 9: прямая ссылка и плееры. Лечение видео-части
конфликтовало бы с его правками, поэтому `video` не участвует в плане, слиянии
и вердикте, а в журнале остаётся причина `video_owned`.

## Пороги и правило приёма

2 попытки в сутки; пауза 6 часов после провала, 24 часа после двух подряд и
после защиты сайта; правка принимается только при починке леченого шага без
деградации соседей — строже общего счёта проверок.

## Чем доказано

- Гейт: `bash .github/scripts/verify-stage10.sh` — 0 FAIL, внутри регрессия
  этапа 8.
- Тесты без сети (`app/src/test/java/eu/kanade/tachiyomi/takami/heal/`): план,
  все запреты правила, вердикт, слияние, журнал.
- CI ветки `takami/etap10-heal`: сборка и юнит-тесты зелёные.

## Что осталось за границей этапа

- Живой прогон по сайтам — дело оператора; чисел с устройства здесь нет.
- Видео не лечится — этап 9.
- «Подождите» показывается целыми часами.
- Пункты меню источников живут в общем файле списка расширений: гейт этапа 1
  теперь разрешает этот путь.
