# Генератор плагинов ранобэ — отчёт проверки

## Что сделано

Инструмент tools/ranobe-plugin-generator: из JSON-конфига сайта собирает
готовый LNReader-совместимый плагин для рантайма новелл Takami
(NovelJsRuntime). Выход: файл плагина с методами popularNovels,
latestNovels, searchNovels, novelDetails, chapterNovelContent — только те,
что описаны в конфиге — и по желанию plugins.json: формат индекса
LNReader-репозитория, который приложение ищет первым (plugins.min.json,
plugins.json, index.json, index.pb, index.min.json; NovelPluginRepoUrls.kt).
Запись индекса несёт sha256 файла плагина и совместима с
tools/lnreader-plugin-converter.

Конфиг описывает: шаблоны адресов листинга и поиска со значениями page и
query, селекторы карточки (item, name, link, cover), страницу новеллы
(поля, теги, главы с датой), главу (content, mode text или html, remove).
Селектор без суффикса берёт текст, селектор@атрибут — атрибут. Сеть плагин
зовёт только через @libs/fetch, разбор — через cheerio, даты — dayjs,
адреса — @libs/isAbsoluteUrl: те же модули, что рантайм даёт плагину.

## Как проверено (полный функциональный прогон)

node tools/ranobe-plugin-generator/test.js — 18 проверок, все зелёные,
без сети (node v22.23.4; страницы сайта заменены приспособлениями):

1. Плагин из примера загружается в песочницу node:vm тем же способом,
   что и NovelPluginScriptBuilder в приложении.
2. popularNovels: три карточки, абсолютные адреса, карточка без ссылки
   отброшена.
3. Подстановка page: второй лист идёт по ?page=2.
4. latestNovels: отдельный шаблон /updates.
5. searchNovels: кодирование запроса, подстановка query и page, две находки.
6. novelDetails: имя, автор, художник, обложка, описание, статус, теги,
   три главы с датами в ISO (dayjs).
7. chapterNovelContent в режиме text: абзацы через перевод строки,
   реклама и скрипт вычищены.
8. Режим html: разметка сохранена, служебные блоки вычищены.
9. Экспорт: только методы из конфига, поля id/name/site/lang/version.
10. Индексная запись: sha256 совпадает с файлом, hasSettings, iconUrl.
11. Командная строка с --index: файл плагина и plugins.json, сумма в
    индексе совпадает с файлом.
12. Правила репозитория в коде плагина: строки до 120 символов, без
    табуляций, без TODO и FIXME, комментарии по-русски.
13. Плохой конфиг отклоняется с понятным сообщением (site, version, mode).
14. Чистка имён файлов; чужие записи индекса не затираются.
15. Синтаксис сгенерированного кода проверен без исполнения.
16. Селектор карточки совпадает с самим элементом: имя и ссылка из него.
17. Массив конфигов в CLI: плагин и запись индекса на каждую запись.
18. Реальный jut.su: живая разметка, предок-ссылка, обложка из url(...), кодировка.
19. Реальный ranobehub: живая разметка, карточки с адресами и именами.

Отдельно пойманы и исправлены в ходе прогона: дубль ключа path в конфиге
листа маскировал шаблон URL (ссылка карточки переименована в link);
валидация конфига вынесена внутрь генератора кода; случайное попадание
node_modules в первый коммит убрано отдельным коммитом. Итог: 18 из 18.

## Повторная проверка (11 ноября)

- Аудит бандled-модулей рантайма (NovelJsRuntime.kt): все методы, которые

  поймано проверкой синтаксиса (№15), продолжение теперь несёт маркер.

## Прогон по живым сайтам (11 ноября)

Снята живая разметка четырёх сайтов (curl с браузерным User-Agent):

- **jut.su** (аниме-каталог, windows-1251): конфиг examples/real-jutsu.json
  проверен на живой разметке — карточки `.all_anime`, имя `.aaname`, ссылка
  через предка `^a@href`, обложка из `style="background: url(...)"`,
  кодировка уходит в `textEncoding`. 18 проверок из 18 зелёные.
- **ranobehub.org** (ранобэ, Next.js): конфиг examples/real-ranobehub.json
  проверен на живой разметке — карточки `.book-card`, ссылка `a@href`,
  имя `h3`, обложка `img.book-cover-image@src`. Зелёный.
- **ranobelib.me** и **animego.org**: страницы собираются в браузере
  (ranobelib отдаёт JS-оболочку, animego закрыт бот-стеной) — SSR-парсер
  тут не справится, честный предел инструмента без WebView.

Новые возможности генератора: `encoding` (textEncoding рантайма),
`headers` (заголовки каждого запроса), селектор предка `^a@href`,
атрибут самого элемента `@href`, обложка из `url(...)` в стиле.

Аудит краш-рисков приложения: вызовы плагина обёрнуты в runCatching
(NovelJsSource.kt:189, 623, 827), рантайм закрывается на путях отказа
(:802), пустые ответы не попадают в кэш — сгенерированный плагин,
упавший на непонятной разметке, даст пустой список, а не краш.
