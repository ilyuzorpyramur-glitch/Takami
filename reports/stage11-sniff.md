# Этап 11. Слой шахты и снимок сети

## Что сделано

Добыча ссылки стала трёхслойной, и каждый слой честно докладывает, чем кончился.

1. **Разметка** — прежняя цепочка плееров. Ссылка теперь несёт заголовки окна:
   `Referer`, `Origin`, `User-Agent` уходят вместе с адресом, иначе поток
   отдаёт отказ. Повторы склеиваются по адресу, непустые заголовки побеждают.
2. **Конфиг** — `MediaMiner` ищет адреса в данных страницы без сети: JSON,
   атрибуты, строки скриптов. Понимает оба порядка полей, `\/`, `\u002f`,
   `&amp;`, base64 и мастер HLS. Длинный плейлист (сезон) фильтруется по
   номеру серии через `PlaylistPick`: нет совпадения — пусто, а не чужая серия.
3. **Снимок** — `MediaSniffer` открывает страницу в окне, ставит зацепку на
   запросы до скриптов страницы и ловит медиа-адреса. Работает только по
   действию человека на экране проверки, снимает окно в любом исходе, держит
   срок и число страниц, не включает JS страницы.

Решения вынесены из окна и проверяются без него: `SnifferState` (дозор после
первой находки, срок, страницы), `MediaFilter` (отсев сегментов, картинок,
`blob:` и `data:`, рекламы, запрещённых доменов; ранг мастер → файл →
плейлист), `SniffMemo` (память домена: две неудачи подряд закрывают слой на
сутки, успех делает снимок предпочтительным на неделю; в файле только домен,
слой, счётчики и время), `SniffPolicy` (домены только для чтения, режим
`never`, отсутствие серий, пауза домена).

## Чем доказано

- Проверки без сети и без задержек: шахта (оба порядка полей, экранирование,
  base64, длинный плейлист, мусор), отбор плейлиста, отбор пойманного, память
  домена, правила снимка, таблица итогов, решения по времени, заголовки.
- Регулярки проверяются на переносимость прежней проверкой.
- Гейт этапа: `bash .github/scripts/verify-stage11.sh` — 0 провалов.
- Прогон сборки и проверок в CI — на ветке `takami/etap11-sniff`.

## Границы

- Снимок не обходит защиту сайта и не подставляет свои данные: заголовки
  берутся у приложения, значения не выдумываются и в файлы не пишутся.
- Домены только для чтения не снимаются ни в каком режиме.
- Ключей и служебных данных в коде, спеке и отчётах нет.

## Что осталось

Живой прогон на настоящих сайтах делает оператор: экран проверки, режим
`fallback`, затем `always` на одном источнике. Итоги по каждому источнику —
`ok`, `no_video`, `no_links`, `blocked`, `drm`, `unavailable`; ноль без
причины больше не выдаётся.
