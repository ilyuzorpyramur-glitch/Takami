# Этап 9: прямая ссылка на видео

Ссылка добывается по спеке: страница серии → все плееры на ней → страница
плеера → карта файлов или мастер HLS. Веток под конкретный сайт в коде нет,
всё различие живёт в полях спеки.

## Что поддержано

| вид | как читается |
| --- | --- |
| строковая карта | `[360p]адрес,[720p]адрес` |
| объектная карта | `{"360": "адрес", "720": "адрес"}` |
| плейлист | массив объектов с `title` и `file` |
| массив адресов | адреса без метки, качество «не определена» |
| одиночный адрес | без метки |
| base64 | раскодируется ровно один уровень |
| мастер HLS | читается один раз на серию, сегменты не запрашиваются |

Цепочка: кадры, объекты, ссылки плееров и поток в разметке. Вложенность по
умолчанию два уровня. Плеер узнаётся по шаблону адреса из спеки, карта может
запрашиваться отдельным шаблоном с подстановкой идентификатора.

## Чего не делаем

- обфусцированный скрипт плеера: нужен исполняющий движок, а не разбор;
- WebSocket и бинарные протоколы плееров;
- DRM и шифрование: нужен ключ, которого у нас нет;
- капчу не обходим вовсе.

Плеер, который не раскрылся, отличается от «ссылок нет»: подпись проверки
пишет «плеер не раскрылся», а короткий тип уходит в сбор провалов.

## Поля спеки

`iframeDepth`, `hosters` (`urlPattern`, `apiTemplate`, `kind`, `idRegex`),
`maxPlayers`, `maxRequests`, `embedAttrs`, `hlsMaster`, `preferred`,
`dubbingMode`. Все новые поля с умолчаниями: спека версии 3 без них читается.

## Потолки

Восемь плееров на страницу, двенадцать запросов на серию, один переход по
переадресации плеера, один запрос мастера на адрес. Потолок исчерпан —
возвращается собранное, без падения.

## Приёмка

```
bash .github/scripts/verify-stage9.sh . origin/main
```

Живой прогон по сайтам делает оператор на устройстве: чисел с устройства
здесь нет намеренно.
